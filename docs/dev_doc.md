# dsh Web Monitor 需求与实现说明（v1.0）

> 本文档按当前 **1.0.1** 版本的实现描述软件的功能范围、行为约定与关键实现选择。

## 0、技术栈与界面

1. 使用 **C# + Windows Forms（`net10.0-windows`）** 实现，输出普通 WinForms 可执行程序。
2. UI 组件使用 **AntdUI 2.4.19**（Apache-2.0）绘制；主窗体保留系统标准标题栏，内容区使用 AntdUI 控件与卡片。
3. 窗口客户区固定 **820×540**（含边框约 **836×579**），不可最大化，单窗口三个 Tab：**主页 / 插件管理 / 日志**；底部为全局状态栏。
4. 高 DPI：`AutoScaleMode.Dpi` 配合 **96 DPI 设计基线**（`AutoScaleDimensions = 96×96`），手工像素定位统一用 `LogicalToDeviceUnits` 换算，进程级 DPI 感知为 PerMonitorV2（`app.manifest` 与 csproj 同时声明）。
5. 外部命令通过 `System.Diagnostics.Process` 异步启动，禁止在 UI 线程同步等待；使用 `WaitForExitAsync` + `OutputDataReceived` / `ErrorDataReceived`。
6. 子进程输出回调投递到日志面板；日志面板在后台线程只入队，由 UI 线程按批合并刷新。
7. 主窗体、托盘菜单、插件页按钮的启用状态全部由同一份 `AppState` 快照驱动，不维护第二套判断逻辑。
8. 最低系统：**Windows 10 1607 / Windows Server 2016**（与 .NET 10、dsh 的 Node 24 要求一致）；不支持 Windows 7 / 8.1。
9. 单实例：优先使用 `Global\DshWebMonitor.SingleInstance` 命名互斥体，受限会话没有全局权限时回退到会话内名称，行为一致；已有实例时把它的窗口带到前台。

## 一、进程识别与身份校验

- 用 `netstat -ano` 找监听指定端口的 PID。解析时按本地地址优先级给候选排序：`127.0.0.1` → `0.0.0.0` → `[::1]` → `[::]` → 其它 `127.*` → 其它地址，同一 PID 只保留一次。
- 身份判定必须同时满足三条：映像名为 **`node.exe`**、命令行命中 dsh 包入口脚本（`…\@deepseek-ai\dsh\lib\bin.js` 或 `…\dsh\lib\bin.js`，按路径段匹配）、入口脚本后紧跟 **`web`** 子命令。仅仅命令行里出现 `dsh` 字样不算 dsh web。
- 「本程序启动进程的后代」优先信任：沿父进程链向上最多 8 层，命中监控器自己启动的进程即认定为本次服务。
- 映像名与命令行优先用 Win32 原生接口读取（`QueryFullProcessImageName`、`NtQueryInformationProcess`），失败时回退 `tasklist` / `wmic` / PowerShell `Get-CimInstance`；系统工具输出按控制台 OEM 代码页解码，避免中文乱码。
- 端口探测结果必须区分「探测失败」与「端口空闲」；连续失败 3 次后按「未运行」收敛，不让状态永久停在检测中。
- 端口被非 dsh 进程占用时状态区显示该进程 PID（进程名写入日志），状态为「端口被其他进程占用」，**禁用停止 / 重新启动**，也不结束该进程。
- **启动路径不做身份校验**：启动前只检查端口是否被占用，不结束其它进程（仅清理本程序上一轮启动留下的包装进程）。
- **停止 / 重新启动前**用最新探测数据重新校验身份（不复用 60 秒展示缓存），并读取进程启动时间；结束时按 **PID + 启动时间二次绑定**，时间不一致即拒绝结束；结束失败返回明确原因（如权限不足），状态收敛回可操作取值。
- 主页归属标签按真实来源显示：本程序启动的进程为「由本程序启动」，外部命令启动的显示「外部启动」，非 dsh 进程占用端口显示「外部进程占用」。

## 二、启动、停止与退出

- **程序固定以管理员权限运行**：`app.manifest` 声明 `requireAdministrator`，启动时由 UAC 提权；拒绝则不会启动。dsh web 及其加载的插件也在同一提权上下文里执行。
- 启动命令固定为 **`dsh web --no-open`**，经 `cmd.exe /d /c` 执行，直接使用全局安装的 dsh CLI，不经过 npm / npx，因此不需要写 npm 缓存。受限环境里系统临时目录不可写时，通过 `TEMP` / `TMP` / `TMPDIR` 让 dsh web 使用应用内可写临时目录（见第三章）。
- 使用 `UseShellExecute = false`、`CreateNoWindow = true`，不弹独立控制台，stdout/stderr 写入日志。
- 60 秒内未进入 LISTENING 视为启动失败：日志回放 stderr 尾部（最多 20 行），结束本次拉起的进程树，并按端口清理本次启动残留的监听进程（同样带启动时间校验）。
- 停止：校验身份 → 结束 dsh web 进程树 → 等待端口释放（最长 20 秒）。超时、探测失败、异常等所有失败分支都显式收敛状态（回到「运行中」并保留 PID 以便重试，或标记端口被占用），不会停在「正在停止」。
- 重新启动 = 校验停止 → 等待端口释放 → 启动 → 等待监听；停止阶段失败即返回，不会在停止未完成时再拉起一个进程。
- 打开 Web UI：未运行时按钮禁用；运行中以 `http://127.0.0.1:3080` 交给系统默认浏览器。
- **退出语义**：退出监控器会结束**由本程序启动**的 dsh web（它的 stdout/stderr 是本进程提供的管道，留在后台会在下次写日志时因 EPIPE 崩溃）；**外部启动**的 dsh web 不受影响。退出确认框按当前监听进程的来源给出对应提示。
- 系统关机 / 任务管理器关闭时放行，不阻止系统关闭。

## 三、npm 全局包与更新通道

- 安装检测：`npm list -g @deepseek-ai/dsh --json --depth=0`；输出无法解析时保持当前安装状态并明确报错，不等同于「未安装」。
- 更新通道：`stable / rc / beta / alpha / next / all`，默认 `stable`。
- 检查更新：`npm view @deepseek-ai/dsh dist-tags --json`，按通道解析目标版本：
  - `stable` 取 `latest`；`latest` 缺失时只回退到**最高的正式版**，不会把 rc / next 当成正式版；
  - `rc / beta / alpha` 取同名 dist-tag；缺失时先从所有 tag 指向版本中取**同一预发布线的最高版本**（例如官方把 `0.2.2-rc.2` 只挂在 `next` 上时，rc 通道仍能解析到），再缺失才回退 `latest`；
  - `next` 取同名 dist-tag，缺失时回退 `latest`；
  - `all` 取所有 tag 指向版本中的最高 semver（含预发布）。
- 当前通道没有更高版本、但其它 tag 指向更高版本时，界面提示该版本与来源 tag（只提示，不跨通道提供更新）。
- 检查失败（npm 命令失败 / 通道无目标版本 / 异常）时把原因写入 `AppState.UpdateCheckError`，界面直接显示「检查更新失败：…」，不会停留在「尚未检查更新」。
- 低完整性 / 受限环境里 npm 默认缓存目录不可写（Windows 报 EPERM）：`NpmCache` 改用应用内可写缓存目录（本地应用数据 → 临时目录 → 程序目录，取第一个可写），并通过 `npm_config_cache` 环境变量让所有 npm / npx 命令共用；普通环境仍使用 npm 自己的缓存（`NpmService` 还保留「命令因写缓存失败后改用 `--cache` 重试一次」的兜底）。
- 同一类环境里系统临时目录（`%TEMP%`）也不可写，dsh web 的 spill-local 等插件会在 `mkdtemp` 时抛 EPERM：`TempDirectory` 按同样的回退顺序取应用内可写目录，并通过 `TEMP` / `TMP` / `TMPDIR` 传给子进程。
- 版本比较统一按 semver（含 `v` 前缀、build metadata、预发布标识）：目标版本必须**高于**已安装版本才提供更新，不会出现降级。
- 更新：`npm add -g @deepseek-ai/dsh@<目标版本>`（按精确版本安装，装上的就是检查到的版本）。
- **dsh 全局包只检测安装状态**；只有用户点击「检查更新」或切换通道后才联网解析目标版本（插件更新检查在启动时进行，见第四章）。
- 「更新」按钮默认隐藏，检查到新版本后出现；更新成功后不自动重启 dsh web。

## 四、插件管理、统计与一键更新

- 统一通过 `dsh plugin --profile web <子命令>` 执行：`list --json`、`add`、`update`、`remove`。
- 安装版本由 `list --json` 解析；最新版本按当前通道用 `npm view <包> dist-tags --json` 解析，并发查询上限 4。单个插件查询失败会记录日志并计入失败数，插件页状态栏标注「N 个最新版本查询失败」，主页「一键更新」按钮改为「检查不完整」（禁用），不谎称已全部最新。
- 包名与版本分别校验：输入框接受 `包名` 或 `包名@版本`，但写入 profile `bundles` 的只有纯包名；包名与版本都会先校验再拼进命令行。
- 启用 / 停用：dsh CLI 未提供对应子命令，通过维护 profile `package.json` 的 `dsh.profile.bundles` 实现，重启 dsh web 后生效。
- 单个更新：`dsh plugin --profile web update <包>@<通道目标版本>`；只有目标版本高于已安装版本时按钮才可用。
- 一键更新：找出当前通道下所有「目标版本高于已安装版本」的插件，逐个执行上述更新，汇总成功 / 失败数量并显示在主页插件概况卡。
- **插件统计口径**：主页与插件页共享同一更新通道；程序启动时读取一次插件列表并按通道解析最新版本，主页与插件页共用这份结果；切到插件页不重复查询，只有「刷新列表」/ 切换通道 / 安装或更新插件后才重新检查。
- 插件页控件启用状态只由 `AppState` + 当前选中行 + 本页进行中的任务派生；全局忙碌时输入框与通道下拉同样禁用。

## 五、日志

- 日志 Tab 使用**单一混合输出面板**，`dsh web` 的 stdout/stderr 与插件 / npm 命令输出按到达顺序显示。
- 颜色区分：命令蓝、系统提示绿、错误红、普通输出深灰。
- 后台日志先入队，由 UI 线程按批合并刷新（同色合并、批次内暂停重绘），每批只滚动一次。
- 仅当用户原本位于底部时自动滚动；用户上翻后暂停跟随，回到顶部/底部区再恢复；裁剪前保存并恢复选择范围，不清除用户选择。
- 内存与界面都只保留最近 **2000 行**（按真实 UI 行数计算，多行条目按行数整条淘汰，不拆分单条）；不写任何磁盘日志文件。
- 日志页右键菜单提供「复制全部」与「清空」。

## 六、系统托盘与窗口行为

- 托盘图标直接基于 `Shell_NotifyIcon` 实现（`TrayIconHost` + 一个隐藏的顶层窗口接收回调），菜单为 **启动 / 停止 / 重新启动 / 打开 Web UI / 分隔线 / 退出**，状态与主窗体同步。
- 可用性判定：先按令牌完整性级别预判（查询失败按「不可用」处理，fail-closed）；注册后校验图标是否真的存在于通知区域；隐藏窗口前再次确认。
- 监听 Explorer 的 `TaskbarCreated` 消息：Explorer 重启后自动重新登记图标；重新登记失败则标记托盘不可用。
- 最小化：只最小化到任务栏，不隐藏窗口。
- 关闭：托盘可用时取消关闭并收起到托盘，双击托盘图标恢复；**隐藏前确认图标仍然有效，确认失败则不隐藏窗口（任务栏按钮保留）并放行关闭，dsh web 正在运行时退出前仍会确认**。
- 托盘不可用（低完整性或注册失败）：不隐藏窗口，关闭窗口即退出（dsh web 正在运行时退出前确认）；最小化仍保留在任务栏。
- 退出：按第二章的退出语义执行（结束由本程序启动的 dsh web，外部启动的不受影响）。
- 系统关机 / 任务管理器关闭时放行，不阻止系统关闭。

## 七、硬性约束

1. 禁止对未通过身份校验的 PID 执行 Kill；Kill 时必须用 PID + 进程启动时间二次绑定，禁止只凭整数 PID 结束进程。
2. 禁止修改注册表；不写日志、配置文件或安装目录以外的路径。例外只有应用自己的数据目录 `%LOCALAPPDATA%\DshWebMonitor\`（`crash.log`、`npm-cache`、`temp`，后两者仅在受限环境回退时使用）。
3. 除 AntdUI 外不引入其他第三方 NuGet 包；JSON 使用 `System.Text.Json`。
4. `dsh plugin` 子命令必须以 `--help` / 实际测试确认，不硬编码臆测命令。
5. 禁止并发执行多个会写全局 npm 目录或 profile 的命令；写操作共用同一互斥闸门，只读查询使用独立的读闸门。
6. 所有外部命令必须有超时：写操作 5 分钟、查询 60 秒、系统工具 10 秒；超时或取消时结束整个进程树并回传 stderr 尾部，不留下孤儿进程，也不因孙进程占用管道而永久挂起。
7. 命令成功语义唯一：**退出码为 0、未超时、且没有明确错误输出**（`CommandResult.IsSuccess`），调用点不得单独比较退出码。
8. profile `package.json` 必须原子写入：同目录写 `.tmp` → `File.Replace` 替换并保留 `.bak`，写入前做 JSON 自检；解析失败只报错，不覆盖原文件。
9. 读取 profile 配置失败时向用户报错，禁止静默当成「全部插件未启用」。

## 八、工程与测试

- 仓库入口：`DshWebMonitor.sln`（解决方案）、`global.json`（固定 SDK 版本）、`.editorconfig`（编码与缩进约定）、`THIRD-PARTY-NOTICES.md`（AntdUI 的 Apache-2.0 归属说明）。
- 发布配置 `SingleFile-win-x64.pubxml`：单文件、framework-dependent（不打包 .NET 运行时），产物输出到 `dist\`；单文件压缩只在自包含模式下可用（framework-dependent 下 `EnableCompressionInSingleFile` 会报 NETSDK1176），因此本发布形态不启用压缩。
- 测试入口：`dotnet run --project tests\DshWebMonitor.SmokeTests`；默认只执行离线用例，加 `--env` 才执行需要真实 npm / dsh / 3080 的集成用例。测试是自包含控制台程序，不引入第三方测试框架，`dotnet test` 不是本仓库的测试入口。
